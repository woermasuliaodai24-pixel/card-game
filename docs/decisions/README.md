# 架构与玩法决策

用于记录会影响架构或玩法、且未来需要解释“为什么这样做”的决定。建议采用轻量 ADR（Architecture Decision Record）。

复制模板新建文件，例如 `0001-pure-battle-model.md`：

```markdown
# <编号>：<决定标题>

- 日期：
- 状态：提议 / 已接受 / 已废弃

## 背景

当时面对的问题和约束。

## 决定

选择了什么方案。

## 后果

带来的收益、成本和后续需要遵守的边界。

## 备选方案

考虑过但未采用的方案，以及未采用的原因。
```

## 已记录的决策

- 战斗规则与 Phaser 表现层分离，规则在纯 TypeScript 中测试。
- 时间以整数毫秒保存，显示时转换为一位小数。
- 平衡数值集中在卡牌/Boss 目录，避免 UI 重复。
