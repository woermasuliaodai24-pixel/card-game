# 《时痕》网页 Demo MVP 与仓库分区设计

日期：2026-11-23
状态：待用户复核

## 1. 目标

建立一个适合两人通过 GitHub 持续协作的项目结构，并交付一版可直接运行和继续修改的网页战斗 Demo。Demo 只验证三类基础牌、以时间代替能量的出牌循环，以及单个 Boss 战的基础体验。

主要实现优先交给 DeepSeek Harness 的 `deepseek-flash`，使用已配置的中科大 token。Codex负责拆解任务、审查代码、独立运行测试和决定是否提交；凭据不进入仓库。

## 2. 技术方案

- Phaser 3：战斗场景、点击交互和轻量动画。
- TypeScript：游戏规则与数据定义。
- Vite：本地开发和生产构建。
- Vitest：纯逻辑单元测试。
- GitHub Actions：在 push 和 Pull Request 时执行测试与构建。

规则逻辑与 Phaser 场景分离。牌库、时间、伤害、格挡和轮次结算必须能在无浏览器环境中测试。

## 4. 战斗规则

### 4.1 玩家与 Boss

- 玩家最大生命：50。
- Boss「毁灭者」最大生命：64。
- 每轮可用时间：3.0 秒。
- 每轮抽牌：5 张。
- 初始牌库：5 张攻击、4 张防御、1 张时间缩放。
- Boss 每轮在时间耗尽后自动攻击，造成 10 点伤害。
- 没有能量、法力或行动点。
- 没有“执行”或“结束回合”按钮。

### 4.2 卡牌

| 卡牌 | 数量 | 耗时 | 效果 |
|---|---:|---:|---|
| 攻击 | 5 | 0.9 秒 | 立即造成 8 点伤害 |
| 防御 | 4 | 0.6 秒 | 立即获得 5 点格挡 |
| 时间缩放 | 1 | 0.3 秒 | 下一张非时间缩放牌的耗时减少 50% |

点击卡牌后立即执行效果、扣除时间并将该牌放入弃牌堆。卡牌耗时可以超过剩余时间；卡牌效果先结算，剩余时间随后归零。

如果攻击先令 Boss 生命归零，则立即胜利，不再结算 Boss 攻击。

### 4.3 自动轮次结算

以下任一条件触发 Boss 攻击：

1. 剩余时间归零；
2. 手牌已经打空但仍有零碎剩余时间。

Boss 攻击时：

1. 当前格挡先抵消伤害；
2. 未被抵消的伤害扣除玩家生命；
3. 当前格挡清零；
4. 未使用手牌进入弃牌堆；
5. 抽牌堆不足时，将弃牌堆洗回抽牌堆；
6. 时间恢复为 3.0 秒并抽取 5 张牌。

玩家生命归零时失败并显示重新开始入口。重新开始是胜负界面操作，不属于执行或结束回合按钮。

## 5. 平衡目标

- Boss 战正常持续 3–4 轮。
- 玩家正常发挥并优先使用抽到的防御牌时，战后平均损失约 5 点生命，即初始 50 生命的 10%。
- 一轮抽 5 张、牌库含 4 张防御时，抽到 0、1、2、3、4 张防御的概率约为 0.4%、23.8%、47.6%、23.8%、2.4%。
- Boss 攻击 10 点、防御牌格挡 5 点时，单轮期望未格挡伤害约为 1.23 点；持续 4 轮约为 4.9 点，符合 5 点目标。
- 攻击牌造成 8 点伤害；平均每轮完成约两次攻击时，64 点 Boss 生命约需 4 轮。

这只是首版平衡基线。数值集中保存在数据文件中，后续可直接修改并由测试保护结算规则。

## 6. 界面布局

- 顶部：Boss 插画、64 点生命和“时间耗尽后造成 10 点伤害”的意图。
- 中部：战斗反馈区域，显示最近一次攻击、格挡、时间缩放或 Boss 结算。
- 左下：玩家 50 点生命与当前格挡。
- 中下：3.0 秒剩余时间条。
- 底部：5 张可点击手牌，以及抽牌堆和弃牌堆数量。

出牌后立即更新数值和反馈。时间缩放激活时，下一张牌显示折扣后的耗时。第一版使用清晰的程序化卡牌 UI；概念图作为美术参考和 Boss 背景，不强行切割为正式卡面素材。

## 7. 数据与模块边界

- `cards/`：卡牌类型、卡牌目录和初始牌库数据。
- `time/`：剩余时间、耗时折扣和耗尽判断。
- `deck/`：确定性洗牌接口、抽牌、弃牌与重洗。
- `combat/`：玩家/Boss 状态、出牌、Boss 攻击、胜负和新一轮。
- `scenes/`：读取纯逻辑状态、接收点击并渲染结果。
- `ui/`：只负责卡牌、时间条、血条、意图和反馈的显示组件。

任何数值修改优先发生在数据定义中，不把平衡数值散落在场景和 UI 文件里。

## 9. GitHub 协作

- 根 README 说明项目定位、目录、启动命令和当前状态。
- CONTRIBUTING 说明功能分支、提交、Pull Request 和禁止提交密钥/构建产物。
- Issue 模板包括 Bug、功能需求和设计想法。
- Pull Request 模板要求描述变更、验证方式和视觉截图。
- GitHub Actions 在 `demo/` 中安装依赖，运行测试并执行生产构建。

## 10. DeepSeek 优先执行流程

1. Codex 将实现步骤写入 `.ai/tasks/`。
2. DeepSeek Harness 在同一工作区读取任务单并完成主要代码和测试。
3. DeepSeek 将摘要写入 `.ai/reports/`，不执行 push、强制重置或历史改写。
4. Codex检查 Git diff，独立运行测试和构建。
5. 不满足规格时，Codex生成精简修正任务，再交给 DeepSeek。
6. 只有验收通过后才提交和推送。

如果 Harness 自动操作受本机授权或会话状态阻塞，停止并请求用户完成授权；不得从 DSH 私有凭据库提取或复制 token。

## 11. 错误与边界处理

- 连续点击期间锁定正在结算的卡牌，避免重复生效。
- 时间使用整数毫秒保存，显示时再转换为一位小数，避免浮点误差。
- 胜利或失败后禁止继续出牌。
- 洗牌支持注入随机函数，测试使用固定序列。
- 图片加载失败时显示程序化 Boss 占位，不阻塞游戏。
- 窄屏允许手牌换行，首版以桌面浏览器为主要验收平台。

## 12. 测试与验收

至少验证：

- 攻击立即扣除 Boss 生命和 900 毫秒；
- 防御立即增加格挡和扣除 600 毫秒；
- 时间缩放扣除 300 毫秒，并只令下一张普通牌耗时减半；
- 超过剩余时间的卡牌先结算，再触发 Boss 攻击；
- 手牌打空时自动结算 Boss 攻击；
- 格挡正确抵消 Boss 的 10 点伤害并在新轮清零；
- 抽牌堆不足时正确重洗弃牌堆；
- Boss 先死亡时不反击；
- 玩家死亡后不能继续出牌；
- 重新开始恢复初始状态；
- `npm test` 通过；
- `npm run build` 通过；
- 页面中不存在能量、执行和结束回合控件；
- 仓库文档、图片和 GitHub 模板位于约定分区。
