# 《时痕》游戏设计大纲 V0.1

> 本文件由项目原始设计大纲整理入库。

## 一、游戏概念

**游戏类型：** 时间驱动型卡牌构筑、实时策略战斗、Roguelike（暂定）

**核心设计：** 将传统回合制卡牌游戏改造为以连续时间为基础的战斗系统。卡牌不再只是即时生效的指令，而是具有前摇、攻击判定、后摇和特殊状态的战斗行为。

**核心主题：** 时间、因果、行动、代价与逆转。

### 核心设计理念

传统卡牌游戏的核心是资源管理：玩家在自己的回合中消耗能量，选择最优卡牌组合。

本游戏希望改变这一逻辑：

- 时间不只是能量，而是玩家与敌人共同经历的战斗过程。
- 卡牌不只是效果，而是角色执行的一段动作。
- 防御不只是增加护甲，而是通过霸体、闪避、招架等动作状态改变攻击结算。
- 卡牌构筑不只是叠加伤害，而是构建一套独特的战斗方式。
- 时间操控不只是延迟敌人攻击，而是重新解释已经发生的战斗事件。

**核心目标：让玩家构筑的不是一套单纯的卡牌，而是一套属于自己的战斗逻辑。**

## 二、核心战斗系统

### 2.1 连续时间机制

取消传统的玩家回合与敌人回合，改为双方共享一条连续时间轴。

玩家和敌人可以同时执行动作。

每轮不再单纯以玩家结束出牌作为结算条件，而是根据双方动作的完成时间、攻击判定时间和特殊状态进行结算。

### 2.2 卡牌动作结构

每张卡牌由四个部分组成：

1. 前摇（Startup）：动作准备阶段。
2. 判定（Active）：攻击、防御或技能实际生效阶段。
3. 后摇（Recovery）：动作完成后的恢复阶段。
4. 取消窗口（Cancel Window）：允许衔接其他动作的特殊时间窗口。

卡牌还可以具有独立属性：

- 霸体：受到攻击时不被打断。
- 无敌帧：特定时间内免疫攻击。
- 招架：在特定时间窗口抵消攻击。
- 打断：中断敌人的动作。
- 蓄力：通过持续准备强化后续效果。
- 延迟：将效果安排在未来某个时间发生。

### 2.3 敌人行为系统

敌人也拥有自己的动作结构。

例如：

| 敌人动作 | 特征 | 玩家应对 |
|---|---|---|
| 普通攻击 | 短前摇 | 闪避或招架 |
| 重型攻击 | 长前摇、高伤害 | 霸体或打断 |
| 抓取攻击 | 无视普通霸体 | 闪避 |
| 范围攻击 | 大范围判定 | 位移或特殊防御 |
| 蓄力技能 | 可被打断 | 抢先攻击 |
| 诅咒攻击 | 附带负面状态 | 净化或时间逆转 |

敌人的攻击需要具有明确的视觉和时间预警，让玩家能够根据卡组做出反应。

## 三、核心机制：时间逆转（Time Reversal）

这是游戏最重要的特色机制。

### 3.1 基础概念

时间逆转不是简单地让整个战场回到过去，而是记录一段时间内发生的特定战斗事件，并在玩家打出卡牌时重新结算。

其核心包括：

- 记录过去一段时间受到的伤害。
- 记录 Boss 施加的负面状态。
- 清除符合条件的负面状态。
- 根据打出时间逆转时 Boss 的当前状态重新结算记录。
- 将记录的伤害转化为反击伤害、增伤、治疗或护盾。

### 3.2 机制流程

**阶段一：时间记录**

战斗系统持续记录最近一段时间，例如6秒内：

- 玩家实际受到的生命值伤害。
- 伤害来源。
- Boss 施加的负面状态及其层数。
- 伤害是否受到负面状态影响。

记录窗口可以随卡牌升级、遗物或其他构筑效果改变。

**阶段二：激活时间逆转**

当记录窗口满足要求，玩家可以打出时间逆转。

此时：

1. 停止当前记录窗口。
2. 清除记录期间由 Boss 施加的可逆负面状态。
3. 统计记录期间受到的伤害。
4. 根据当前 Boss 状态进行重新结算。

**阶段三：因果重新结算**

特别重要的一点：

不是根据玩家受到伤害时的 Boss 状态结算，而是根据打出时间逆转时 Boss 的状态结算。

例如：

- 过去6秒，玩家受到30点伤害。
- Boss 给玩家施加了裂伤，使玩家受到的伤害增加。
- 玩家打出时间逆转。
- 裂伤被清除。
- 记录的伤害转化为逆转能量。
- 此时 Boss 正处于破绽状态，逆转能量转化为额外伤害。

这样，玩家需要考虑的不仅是何时受到伤害，还包括何时发动时间逆转。

### 3.3 Boss 状态与时间逆转的交互

| 打出时间逆转时的 Boss 状态 | 逆转结果 |
|---|---|
| 普通状态 | 将记录伤害转化为普通反击 |
| 破绽状态 | 反击伤害获得额外倍率 |
| 霸体状态 | 反击受到削弱，但保留部分恢复效果 |
| 防御状态 | 将部分逆转能量转化为生命恢复或护盾 |
| 狂暴状态 | 反击伤害增加，但玩家恢复效果降低 |
| 无敌或阶段转换 | 储存逆转能量，等待下一次可攻击窗口 |

这样一来，同一张时间逆转牌，在不同时间使用会产生完全不同的效果。

### 3.4 数值示例

假设玩家在过去6秒内：

- 实际损失生命值：30点。
- 获得Boss施加的2层裂伤。
- 裂伤增加受到的伤害，并在时间逆转时可以被清除。

设定基础转换比例：

- 40%转化为生命恢复。
- 60%转化为逆转能量。

因此：

生命恢复：

30 × 40% = 12点。

逆转能量：

30 × 60% = 18点。

如果此时Boss处于破绽状态，反击倍率为1.5：

18 × 1.5 = 27点反击伤害。

如果此时Boss处于防御状态，则可以将这18点逆转能量转换为护盾或额外生命恢复。

以上数值仅为初始平衡示例，具体比例需要通过测试确定。

### 3.5 时间逆转的限制

为了防止无限循环：

- 只记录指定时间窗口内的有效伤害。
- 自身主动消耗生命值不计入记录。
- 时间逆转产生的反击伤害不能再次进入记录。
- Boss施加的不可逆特殊状态不一定能够清除。
- 每次发动后需要重新积累记录窗口。
- 记录伤害存在上限。

## 四、卡牌构筑系统

卡牌构筑不再单纯按照攻击、防御、辅助分类，而是围绕不同的动作机制和时间关系展开。

### 4.1 核心卡牌类型

| 类型 | 主要作用 |
|---|---|
| 蓄力牌 | 通过持续前摇获得强力效果 |
| 霸体牌 | 在承受攻击时维持动作 |
| 闪避牌 | 利用无敌窗口规避攻击 |
| 招架牌 | 精准抵消敌人攻击并创造反击机会 |
| 连招牌 | 取消后摇、衔接动作 |
| 延迟牌 | 将效果安排在未来发生 |
| 记录牌 | 记录伤害、状态或战斗事件 |
| 逆转牌 | 重新结算已经发生的事件 |
| 操控牌 | 改变双方的行动时间和顺序 |

### 4.2 主要构筑流派

**A. 霸体反击流**

通过主动承受伤害维持攻击动作。

- 受击时增加攻击伤害。
- 蓄力期间受到攻击，强化最终攻击。
- 生命值越低，霸体期间获得的收益越高。

**B. 精准招架流**

通过精准的时间窗口创造反击机会。

- 完美招架后下一张牌瞬发。
- 连续招架增加连击层数。
- 招架成功可以取消后摇。

**C. 时间逆转流**

主动记录伤害和负面状态，再将其转化为恢复或反击。

- 记录窗口延长。
- 受到负面状态时增加逆转能量。
- 逆转时清除更多负面状态。
- 破绽期间发动逆转，获得额外伤害。

**D. 时间延迟流**

通过延迟效果安排未来行动。

- 延迟攻击。
- 延迟治疗。
- 复制上一张卡牌并在未来执行。
- 将敌人的攻击延迟到指定时间。

**E. 连招流**

通过取消窗口构建连续动作。

- 攻击后接突刺。
- 闪避后接反击。
- 重击命中后取消收招。
- 特定卡牌之间形成特殊连锁。

## 五、卡牌之间的机制联动

卡牌之间的关系应该超越单纯的数值加成。

例如：

| 卡牌组合 | 联动效果 |
|---|---|
| 霸体蓄力 + 时间逆转 | 蓄力期间承受伤害，之后逆转恢复并反击 |
| 完美招架 + 时间逆转 | 招架成功后增加逆转倍率 |
| 延迟爆炸 + 时间回溯 | 将爆炸效果重新安排到敌人破绽期间 |
| 连续攻击 + 时间记录 | 连击期间记录伤害，结束后集中结算 |
| 负面状态承受 + 时间逆转 | 清除负面状态，并将记录的负面状态强度转化为逆转收益 |

这里需要注意：卡牌联动不应只是简单的伤害乘法，而应该创造新的动作、时间关系和结算方式。

## 六、Boss战设计

Boss不仅是拥有大量生命值的敌人，还应该是时间机制的测试对象。

每个Boss应该有独特的攻击节奏、特殊状态和负面效果。

例如：

### Boss A：毁灭者

- 攻击前摇较长。
- 重型攻击无法被普通霸体抵消。
- 经常施加裂伤。
- 适合霸体反击流和时间逆转流。

### Boss B：时序观察者

- 能够改变自己的攻击时间。
- 可以制造延迟攻击。
- 某些攻击会在玩家发动卡牌后触发。
- 适合招架流和时间操控流。

### Boss C：熵之化身

- 不断积累狂暴层数。
- 会周期性进入无敌状态。
- 玩家需要在不同阶段选择逆转时机。
- 适合延迟流和因果逆转流。

Boss应该具有可以被玩家学习和利用的行为规律，而不是依赖随机攻击制造难度。

## 七、视觉表现与动画技术

前面讨论的二维曲线拓扑动画系统，可以作为本游戏后续的视觉技术基础。

### 7.1 参数化动画

采用参数曲线：

P(s,t) = (x(s,t), y(s,t))

分别控制曲线上的位置和动画时间。

动画变化拆分为：

- 几何变化：攻击轨迹、法术形状和角色动作。
- 可见性变化：遮挡、显现、消失。
- 连接关系变化：攻击轨迹的断裂、连接和重新激活。
- 区域变化：攻击范围、护盾区域和特殊效果的填充。

### 7.2 时间逆转的视觉表现

时间逆转不需要让整个战场倒放，而是让被记录的事件产生逆向动画。

例如：

1. 玩家受到攻击时，出现红色时间痕迹。
2. 伤害记录在时间轴上形成节点。
3. 玩家发动时间逆转。
4. 时间痕迹沿原路径逆向运动。
5. 负面状态逐渐消散。
6. 记录的能量重新汇聚。
7. 根据Boss当前状态，能量转化为攻击、治疗或护盾。

这样，玩家能够直观理解时间逆转的因果关系。

### 7.3 嵌套环二维表示

此前讨论的嵌套环表示法可以作为攻击区域、技能范围和复杂空间效果的表达方式。

通过闭合曲线和嵌套区域，表达：

- 攻击范围。
- 安全区域。
- 多层护盾。
- 特殊技能区域。
- 区域之间的连接关系。

这部分属于后续视觉和程序技术储备，不必在第一版原型中实现。

## 八、游戏整体循环

暂定采用单人PVE卡牌构筑模式。

1. 进入战斗。
2. 根据初始卡组与敌人交战。
3. 通过时间轴管理动作与攻击窗口。
4. 根据战斗表现获得新的卡牌或强化。
5. 逐步构建自己的战斗机制。
6. 挑战特殊敌人和Boss。
7. 通过不同卡牌组合探索不同战斗流派。

每次游戏流程中，玩家都可以构建不同的战斗方式。

---

## 九、第一阶段开发目标（MVP）

不建议一开始就实现所有系统。

第一版只需要验证三个问题：

**1. 时间战斗是否真的有趣？**

- 一个可操作角色。
- 一个Boss。
- 10至15张卡牌。
- 卡牌拥有前摇、判定和后摇。
- Boss具有攻击预警。

**2. 动作交互是否产生策略深度？**

- 霸体。
- 闪避。
- 招架。
- 打断。
- 后摇取消。

**3. 时间逆转是否能改变战斗策略？**

- 6秒记录窗口。
- 伤害记录。
- Boss负面状态清除。
- Boss状态识别。
- 反击与恢复两种结算结果。

只有当这三个系统组合后确实产生有趣的战斗决策，再扩展卡组、遗物、Boss和其他时间操控能力。

---

## 十、核心设计总结

这款游戏最重要的不是时间条，也不是时间逆转这张卡牌。

而是建立一种新的卡牌战斗逻辑：

**卡牌决定行动，时间决定行动的过程，敌我状态决定行动的结果，而时间操控允许玩家重新定义已经发生的结果。**

玩家最终构筑的不仅是一套能够造成更高伤害的卡组，而是一套能够改变战斗因果关系的系统。
